# Technical Plan: Darwin Sidecar Sliding-Window Activity Heartbeat & Inactivity Watchdog

**Jira Tracking:** [VMER-2321](https://redhat.atlassian.net/browse/VMER-2321) (plan attached)  
**Parent Epic:** [VMER-62](https://redhat.atlassian.net/browse/VMER-62) (AI SDLC 2026 - Darwin)  
**Canvas Brief:** `architect-brief.canvas.tsx` · `architect-brief.html`

---

## 1. Problem & Goals

### Problem Statement
During long-running agent tasks (e.g. mutation testing in `evt-2aae6f01`), subagent sidecars experience sudden disconnections and fatal aborts. Forensic root-cause analysis revealed compounding architectural defects:
1. **Static Node.js Process Spawn Timeout:** `BlackBoard/gemini-sidecar/cli-executor.js` spawns child CLI processes with `{ timeout: resolveTimeoutMs(role) }`. Node's native `spawn` timeout is an immutable, one-shot OS timer that sends `SIGTERM` (exit code 143) after exactly 1,800,000ms (30m), completely oblivious to ongoing stdout/stderr activity or active tool execution.
2. **Dual-Timer Incoherence in `ws-client.js`:** The WebSocket client watchdog timer (`TASK_TIMEOUT_DEFAULT = 600s`) only resets when receiving explicit `{ type: 'progress' }` messages containing non-empty text chunks. During extended computation or tool runs where the child produces raw progress or stderr, `ws-client.js` can prematurely abort at 600s before `cli-executor.js` reaches its inactivity ceiling.
3. **Stale Output Masking on Timeout / Crash:** When the child process is terminated with code 143, `BlackBoard/gemini-sidecar/cli-executor.js` resolves `{ status: 'failed', stdout: effectiveOutput }`. `effectiveOutput` contains whatever assistant text was accumulated earlier in the task (e.g., Turn 43: *"only 9 of 123 mutants had finished when I was told to report"* from 27 minutes prior). `BlackBoard/gemini-sidecar/ws-client.js` falls back to `result.stdout` when `result.output` is undefined. Brain wraps this in `Error: `, misinterpreting it as an agent decision to abort, and clears the session as corrupted.

### Goals
1. **Eliminate Static Spawn Timeout:** Remove static `timeout` from `child_process.spawn()` in both `executeCLI` and `executeCLIStreaming`. Working CLI processes must never be killed while actively producing output.
2. **Sliding-Window Activity Watchdog:** Implement an active watchdog timer in `cli-executor.js`. Every chunk of data received on `stdout` or `stderr`, and every parsed stream event, resets the inactivity window.
3. **Harmonized Activity Reset in Transport:** Ensure every stream data chunk from the child triggers activity resets in `ws-client.js` (`wsProxy.onActivity?.()`), preventing premature 600s task timeouts during active execution.
4. **Truthful Inactivity Termination:** Only if a child process produces zero output for the entire inactivity window (hung process / infinite loop) does the watchdog send `SIGTERM` (followed by `SIGKILL` after a 10s grace period if unresponsive).
5. **Honest Error Abstraction:** When terminated due to inactivity, the sidecar must set `result.output = 'Task execution timed out: no output received for X minutes'`, set `result.timedOut = true`, and suppress stale stdout so interim assistant text cannot masquerade as the fatal error payload.
6. **Leak-Free Timer Lifecycle:** Ensure watchdog timers are guaranteed to clear on `child.on('close')`, `child.on('error')`, and early process termination.
7. **Red-First ATDD Verification:** Provide executable 4-layer acceptance test specifications in `BlackBoard/gemini-sidecar/tests/cli-executor.test.js` covering active process preservation, genuine inactivity termination, error payload integrity, and clean timer teardown.

### Non-Goals
- Changing Brain's Cynefin triage or event document schema in Redis.
- Modifying subagent roles or prompt instructions.
- Altering Claude CLI / Antigravity command line argument generation (`buildCLICommand`).

## 2. Constraints & Prior Art

- **Control Theory Mandate:** Follow **"Railways, Not Guardrails"**. The controller must sense the process variable (active I/O streaming) rather than enforcing an arbitrary static time limit.
- **Node.js Subprocess Constraints:** Node's `child_process.spawn({ timeout })` must NOT be used because its internal timer cannot be reset. All timeouts must be managed via explicit user-space Node `setTimeout` / `clearTimeout` handles.
- **Path & Link Hygiene:** All source paths must remain repo-relative (`BlackBoard/gemini-sidecar/...`) with zero `file:///` URLs or developer home paths.
- **Test Harness Parity:** `gemini-sidecar` tests use Node's native `node:test` and `node:assert/strict` with `mockSpawn` patterns. Tests must execute within `node --test tests/cli-executor.test.js`.
- **Docs-Hub:** No conflicting or existing sidecar RFCs exist in `openshift-virtualization/docs-hub/Plans/`.

## 5. Atomic Execution Steps

### Step 1: ATDD Test Suite (`BlackBoard/gemini-sidecar/tests/cli-executor.test.js`)
- **Cynefin:** `Complicated`
- **Action:** Author executable Farley ATDD scenarios in `cli-executor.test.js`:
  - `T-20 (Heartbeat Keeps Active Process Alive)`: Spawn a mock child that emits periodic data chunks past the initial timeout threshold. Assert process completes successfully and is never killed.
  - `T-21 (Genuine Inactivity Triggers Timeout)`: Spawn a mock child that falls silent past the inactivity timeout. Assert child is killed with SIGTERM and resolves with `status: 'failed'` and `timedOut: true`.
  - `T-22 (Truthful Error Message on Timeout)`: Verify that when an inactivity timeout fires, `result.output` explicitly states `Task execution timed out: no output received for X minutes` and stale partial stdout is suppressed.
  - `T-23 (Clean Watchdog Teardown on Error/Close)`: Verify watchdog timer is cleared when process exits normally, encounters a spawn error, or is cancelled, leaving no unhandled timers.
  - `T-24 (Dual-Timer Sync via onActivity)`: Verify that `wsProxy.onActivity` is invoked on each raw `stdout`/`stderr` chunk, resetting transport-level timers in lockstep.
- **Verification:** `node --test tests/cli-executor.test.js` (red state).

### Step 2: Inactivity Watchdog in `BlackBoard/gemini-sidecar/cli-executor.js`
- **Cynefin:** `Complicated`
- **Action:**
  - Remove `timeout: resolveTimeoutMs(...)` from `child_process.spawn()` in both `executeCLI` and `executeCLIStreaming`.
  - Implement helper `createInactivityWatchdog(child, timeoutMs, onTimeout)`:
    - Maintains an active `setTimeout`.
    - Exposes `.reset()` to restart the inactivity timer.
    - Exposes `.clear()` to clear the timer safely.
    - On timeout expiration: sets `child._timedOut = true`, triggers `child.kill('SIGTERM')`, and schedules a 10s fallback `child.kill('SIGKILL')` if still running.
  - Wire `child.stdout.on('data')`, `child.stderr.on('data')` to call `watchdog.reset()` and `options.ws?.onActivity?.()`.
  - In `child.on('close')` and `child.on('error')`: call `watchdog.clear()`.
  - In `child.on('close')`: If `child._timedOut` is true (or signal === 'SIGTERM' and `child._timedOut`), set:
    - `result.status = 'failed'`
    - `result.timedOut = true`
    - `result.output = \`Task execution timed out: no output received for \${Math.round(timeoutMs / 60000)} minutes\``
    - `result.stdout = ''` (suppress stale interim text)
- **Verification:** `node --test tests/cli-executor.test.js` (green state).

### Step 3: Stream Activity Synchronization in `BlackBoard/gemini-sidecar/ws-client.js`
- **Cynefin:** `Complicated`
- **Action:**
  - Attach `onActivity` to `wsProxy`: `wsProxy.onActivity = () => resetTimer();`.
  - In `executeCLIStreaming` call in `ws-client.js`, pass `wsProxy`.
  - In `ws-client.js:352-358`, ensure that if `result.status === 'failed'` or `result.timedOut`, stale `state.getCallbackResult()` is never used to overwrite the failure output.
  - In `ws-client.js:372`, send `output: result.output || result.stdout || ''`, which now reliably carries the explicit timeout message.
- **Verification:** `node --test tests/test_event_transport.js` & `node --test tests/cli-executor.test.js`.

## 7. Definition of Done (DoD)

- [ ] Node's static `spawn({ timeout })` is removed from all execution paths.
- [ ] Inactivity watchdog resets on every `stdout` and `stderr` data event.
- [ ] `wsProxy.onActivity` resets `ws-client.js` task timer on every child data chunk.
- [ ] Child process is only terminated if completely silent for the full timeout window.
- [ ] Timeout exit (code 143 / SIGTERM) sets `result.output` to an explicit inactivity message and suppresses stale stdout.
- [ ] Stale `callbackResult` never clobbers fatal task exit payloads.
- [ ] Zero `file:///` URLs or developer home paths in plan and source references.
- [ ] All 4-layer ATDD tests pass (`node --test tests/cli-executor.test.js`).
